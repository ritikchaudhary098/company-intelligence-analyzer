
Company Intelligence Analyzer
A Python command-line tool that accepts a public company website URL, collects available website text, searches Google News RSS for recent company-related articles, and uses a Groq-hosted language model to produce a structured company intelligence report.

Features
Accepts a company domain or URL from the command line.
Extracts text from the homepage and selected same-site pages.
Searches Google News RSS for recent news metadata.
Uses Groq to summarize the business model and target customer persona.
Produces a recent business-trigger summary when the supplied evidence supports one.
Labels the operational bottleneck as a hypothesis rather than a confirmed fact.
Validates the result with Pydantic and prints JSON to the terminal.
Saves each result as a separate JSON file in reports/.

Setup with uv
From the project directory:

Create a virtual environment if you do not already have one:

uv venv
Install the dependencies:

uv pip install -r requirements.txt
Alternatively, if you manage dependencies with uv add, run:

uv add requests beautifulsoup4 groq python-dotenv pydantic
Create your local environment file by copying the example:

cp .env.example .env
Open .env and replace the placeholder with your own Groq API key:

GROQ_API_KEY=your_actual_groq_api_key
GROQ_MODEL=openai/gpt-oss-120b
Keep .env private. Never commit or share your real API key.

Run the analyzer
Pass a company domain or URL:

uv run python app.py https://stripe.com
You can also try another public company website, for example:

uv run python app.py https://www.shopify.com
The program prints progress messages to the terminal's standard error stream and the final JSON report to standard output. The generated report is saved under reports/. If a report with the same filename already exists, the program creates a numbered filename instead of overwriting it.

Output format
The JSON response uses these fields:

{
  "company_name": "Example Company",
  "analyzed_url": "https://example.com",
  "business_summary": {
    "model": "A concise description of how the company operates and earns revenue.",
    "target_persona": "The main customer, buyer, or user."
  },
  "key_business_trigger": {
    "headline": "A recent event supported by the supplied search result metadata.",
    "date_or_timeframe": "YYYY-MM-DD or an explicit unknown value",
    "source_relevance": "Why the event could matter to the company, with evidence limits stated."
  },
  "operational_bottleneck_hypothesis": "Hypothesis: A plausible but unverified operational or technical bottleneck.",
  "execution_metadata": {
    "model_used": "openai/gpt-oss-120b",
    "latency_seconds": 2.42
  }
}
The values above are illustrative examples of the schema, not claims about a real company.

How it works
Input validation: checks the provided URL and rejects local/private destinations.
Website collection: fetches a limited number of public HTML pages and extracts readable text.
News discovery: searches Google News RSS and collects headline, publication date, source, and URL metadata.
LLM analysis: sends the collected website text and news metadata to Groq.
Schema validation: validates the response using Pydantic.
Report saving: prints JSON and saves a separate JSON report in reports/.
Important limitations
Some sites block automated requests, require JavaScript, redirect to unsupported hosts, or return errors for common page paths.
The website crawler collects only a limited number of pages and may not discover all relevant content.
Google News RSS results are search-result metadata. The program does not independently verify the full contents of each linked article.
A headline and publication date should be checked against the original source before treating a business trigger as confirmed.
The operational bottleneck is a hypothesis generated by an LLM, not a verified internal fact about the company.
Model output can still contain mistakes. Verify important claims and avoid presenting unsupported numbers as facts.
The tool is intended for public company information, not authenticated or private systems.
Troubleshooting
GROQ_API_KEY is missing
Make sure a .env file exists in the project directory and contains GROQ_API_KEY=....

The website text cannot be extracted
Try the company's canonical public website URL. Some sites block automated requests or redirect to a different domain. A failure to fetch a page does not necessarily mean the website is down.

Some pages return 404 warnings
The crawler tries selected common paths. A 404 on an optional path is expected; the run can continue if it successfully extracts text from at least one page.

No recent news results are found
Search results depend on the company's name, domain, news coverage, and Google News RSS availability. The analyzer should report a lack of verified evidence instead of inventing a recent event.

Security
Never commit .env, API keys, or other credentials.
Respect website terms of service, robots policies, rate limits, and applicable laws.
Only analyze publicly accessible pages you are permitted to access.
Review all generated claims before using them for business decisions.
